# Running-app XAML inspection: bootstrap design

Status: launch-time inspection, picking/highlighting, layout observation/overlays, explicit temporary property editing, deeper binding evidence, checked object-source navigation and reviewed local XAML edits are implemented for untrimmed .NET 8–10 WPF applications. This extends the isolated source preview with inspection of an application explicitly launched for inspection by WpfStudio. Arbitrary attachment to an already-running process remains a separate capability. The full acceptance matrix below includes work beyond this increment; see [VALIDATION.md](../VALIDATION.md) for measured coverage rather than treating implementation as a completed compatibility test.

## Implemented workflow

**Run with XAML inspection** and **Debug with XAML inspection** rebuild the startup project with the command-line `XamlDebuggingInformation=true` property, then resolve its program, arguments, working directory and launch profile. No project-file change is required. The hook is applied to the target environment; the build and debugger adapter are not instrumented. The normal launch commands remain available.

`WpfStudio.Inspection.StartupHook` and `WpfStudio.Inspection.Agent` target .NET 8; `WpfStudio.Inspection.Protocol` carries bounded, length-prefixed JSON records shared with the .NET 10 IDE. The bootstrap loads only its agent, protocol and shared `WpfStudio.Wpf.PropertyEditing` and `WpfStudio.Wpf.Diagnostics` assemblies in a collectible load context and shares WPF/framework identities with the target. It installs a bounded binding listener before Main and schedules connection work without waiting for I/O or a dispatcher. It removes its own hook and session variables before application code can launch children, preserving unrelated hooks.

The IDE verifies the agent's actual named-pipe client process ID, protocol and per-launch token; the agent verifies the server PID before sending the token. Requests are serialized. Property mutation requires an explicit edit request against an observed property token; picking temporarily intercepts selection input and displays inspector-owned adorners. Cancellation, malformed frames, missing peers, deadlines and disconnect never terminate the application. The debugger's stopped state suspends inspection and its handshake budget; the agent tolerates a long managed-thread suspension during handshake. Normal profile overrides, including an explicitly empty startup-hook list, remain effective. The launch adapter's inherited hook value is isolated because the pinned netcoredbg otherwise appends it to `launch.env`.

The session retains its collectible load context until connection work and inspector cleanup finish, then requests unloading. This ownership also covers libraries resolved lazily on a later inspection request. The runtime can otherwise initiate unloading from the collectible context's finalizer; see the [runtime implementation](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Private.CoreLib/src/System/Runtime/Loader/AssemblyLoadContext.cs). Target-side forced collection before the first property/layout inspection is covered across .NET 8–10.

`RunningInspector` uses existing presentation sources and their owning dispatchers. Its identities and retained object references are weak. Snapshots are bounded to 3,000 nodes across at most 64 presentation sources, with dispatcher timeouts and traversal limits. The Live XAML pane refreshes every two seconds when enabled and shows current DataContexts, binding expressions, effective dependency-property values and origins. Simple missing CLR properties and failing MultiBinding children receive specific explanations without traversing model getters. Up to 200 historical trace groups are retained; lack of a new trace is not treated as proof of recovery. Source URI/line hints require the separate verification chain below before **Show XAML** navigates; they never authorize source writes by themselves.

The Bindings tab shares its [explanation panel and reader with preview](xaml-binding-diagnostics.md). The selected root or composite child is identified by its actual expression/declaration IDs; live issues refresh and select that exact expression rather than a matching path. **Current binding details**, **Current validation**, and **Historical WPF evidence** remain separate. Current details report configured source kind and mode, converter type, and available cached source/resolved owner/member. Validation rows report current rule type, validation step, safe scalar message and exception type. The property target value is not a composite child's intermediate transfer value. Selection preserves a property edit draft and is invalidated when its expression is replaced.

`WpfStudio.Wpf.Diagnostics.BindingPathStateReader` adds a bounded cached prefix and first unresolved step where WPF retains sufficient state. It reads private fields only on the target dispatcher, guards WPF major versions 8–10 and exact implementation shapes, and rejects changed or inconsistent observations. Unsupported shapes, XPath and absent CLR workers return an explicit unavailable reason; pending/deferred/inactive states withhold downstream interpretation. The reader invokes no source getters, converters or custom descriptor metadata. WPF can erase the failed segment's owner, so the first unresolved step alone cannot distinguish a missing member from a null intermediate value. It does not expose raw source values. Current public status and other details can remain available without cached steps. This describes implementation, not a claim that every runtime patch has been validated.

The **Layout** tab uses the same bounded `WpfStudio.Wpf.Diagnostics.LayoutReader` as the isolated preview. Its optional protocol payload reports cached desired/render/actual sizes, the parent-assigned layout slot, dimensions, margins, alignment, padding/border values, transforms, visibility and DPI. It does not force measure/arrange or invoke virtual layout-clip callbacks. Overlay vertices use the presentation root's DIPs; the inspector draws them through a non-interactive adorner layer. Slot (cyan), render box (green), margin (orange) and cached clip bounds (purple) are distinct. `layout` and `layout-overlay` capabilities are additive to protocol v1, and older highlight requests retain their original behavior.

These are last-observed facts: refresh after layout changes. The original measure constraint and exact visible region are not inferred. Clip outlines are bounding approximations; complex/custom geometry is omitted. Unsupported transforms/effects, pending layout, detached elements and collapsed ancestry withhold overlays with an explanation. Ancestor traversal, transform/geometry traversal and clip outlines are bounded. Temporary overlay state is cleared on selection/session invalidation and pause/resume; live overlays require an available adorner layer. No source or layout property is changed by observation.

Structured `BindingDiagnostics.BindingFailed` notifications add historical evidence for supported .NET 8–10 WPF codes, including missing nested members, null path items, conversion/formatting failures and source getter/update failures. Events carry their observed timestamp, code, status, path and available member/owner/source facts. They are not promoted to the current failure cause. Root-source identity comparisons use weak references: a match says nothing about whether nested objects or values changed, and a notification can outlive recovery. Retention is limited to 500 expressions and four events per expression; responses include at most two recent events per expression, three merged child events and four current validation rows. Aggregate diagnostic-text budgets omit additional details explicitly.

The pinned debugger cannot detach from a target it launched: its [managed implementation rejects that operation](https://github.com/Samsung/netcoredbg/blob/3.2.0-1092/src/debugger/manageddebugger.cpp#L288), while its [DAP disconnect handler discards the failure](https://github.com/Samsung/netcoredbg/blob/3.2.0-1092/src/protocols/vscodeprotocol.cpp#L580). WpfStudio now rejects that unsupported request before tearing down the adapter. Detaching an attached process remains supported. Disconnecting only the XAML inspector is independent and preserves both the application and any debugger session.

Tree snapshots also carry up to 1,000 binding observations and the identities of nodes completely scanned for supported binding properties. Each presentation source gets an output share, a 120 ms scan budget, and weak rotating node/property cursors so later elements make progress. Discovery covers local and declared dependency properties, explicit Style/BasedOn setters/triggers, template triggers, and previously observed bound properties. Unusual hidden attached-property registrations may not be discoverable through these public surfaces. The IDE retains up to 500 issues and tracks each expression by a weak, stable agent identity. Issues are grouped for presentation while preserving individual target instances, observed failure episodes and lifecycle states. Only a later successful observation of the same expression establishes recovery. Inactivity, missing observations, expression replacement/removal, unloading and session end remain distinct. Conflicting duplicate observations prefer failure or unverified evidence over success. Incomplete tree or binding scans cannot establish removal of an unobserved target; history retention is bounded separately from scan coverage. Polling cannot count failures that occur entirely between observations.

Runtime picking uses a per-dispatcher [WPF input preprocessing filter](https://learn.microsoft.com/en-us/dotnet/api/system.windows.input.inputmanager.preprocessinput?view=windowsdesktop-10.0), consuming a left-button pick before normal routed control actions. Escape cancels. A sequence number prevents stale snapshots from undoing newer picker state. The IDE polls while picking even when regular refresh is disabled. Noninteractive adorners highlight hover/selection where a visible adorner surface exists; unsupported surfaces return an explanation. The agent excludes its adorners from tree snapshots and removes its handlers and overlays on cancel/disconnect. Cleanup for an unresponsive dispatcher remains queued and callbacks become inert when the agent is disposed.

The Live XAML Properties tab provides **Validate**, **Try value**, **Reset override**, **Reload value** and **Check edit outcome**. The shared editor uses an inspector-owned constant OneWay binding so replacing supported TwoWay bindings does not write the trial value into their source. Reset clears originally nonlocal values to restore style/template/inheritance precedence, reattaches original local bindings, or restores original local literals. It checks ownership first: application replacements are preserved and reported as conflicts. Targets and saved binding/value graphs use conditional weak storage; a bounded weak index supports restoration even after an edited object has left the presentation tree. Detach and abrupt EOF attempt restoration on each owning dispatcher, alongside input/adorner cleanup.

Temporary editing supports a restricted set of scalar types through explicit parsers and framework converters, without application type-description providers. Null is separate from empty text; editable strings are not truncated display values. Current text beyond the scalar limit is omitted from editable metadata and editing is disabled with a size-limit explanation. OneWayToSource bindings, including those inside composite bindings, are rejected because reattaching them can itself write to the source. Animated properties, dynamic resources and unsupported expressions, rich TextBlock inline replacement and complex object-content replacement are rejected. These limitations remain editing work; they are not silently treated as safe resets. Validation calls WPF property validation, and applying/restoring a property can invoke application callbacks. Restoring a property's configuration cannot reverse their arbitrary effects.

Each live mutation carries an operation ID, tree revision, opaque property ID and observed-state token. Stale identity/value/binding/source evidence rejects the edit. Outcomes distinguish Applied, Reset, Rejected, Conflict and Unknown. The agent retains at most 1,024 operation receipts; reusing an ID cannot execute a mutation twice. A queued operation cancelled before execution is rejected. Once a callback begins, a timeout reports Unknown and the UI queries its receipt rather than automatically replaying it. The shared editor retains at most 256 temporary properties and accepts at most 65,536 characters per scalar. Live property snapshots include at most 262,144 editable text characters in total; excess values are omitted with an explicit editing-disabled reason rather than truncated. Existing owned overrides retain reset-only tokens. Dispatcher waits are bounded to two seconds; weak cleanup remains queued if the dispatcher is blocked, and executing callbacks cannot be safely aborted.

The Properties tab also offers **Review XAML value…** and **Review local removal…**. They prepare a diff for the exact authored element after the source verification below and independent property validation. Applying updates the editor buffer through the existing workspace transaction and undo flow. It does not set the live property, reset an override, rebuild the application or perform Hot Reload. Save and rebuild with inspection to establish a new source baseline before further live source changes.

Supported binding declarations have a separate [verified navigation flow](xaml-binding-navigation.md). Editing shared style/resource origins, safe temporary OneWayToSource restoration and broader expression editing, incremental tree updates, complete current null/missing/conversion attribution, arbitrary post-startup attachment and broad input/DPI/layout fidelity remain outstanding. WPF tree overrides or dependency-property callbacks can execute application code during framework reads. Input preprocessing tests establish normal WPF routed-input behavior, not arbitrary application-installed low-level input hooks.

## Verified platform behavior

- .NET startup hooks run before `Main` on its thread, with its configured apartment state. A hook declares an internal, global-namespace `StartupHook` type and `public static void Initialize()`. `DOTNET_STARTUP_HOOKS` accepts absolute assembly paths separated by `;` on Windows. Hook dependencies do not receive automatic adjacent-directory probing; hook binaries must target the same or an older runtime than the application. An uncaught hook exception can terminate startup, and trimming disables hooks by default. [Runtime startup-hook design](https://github.com/dotnet/runtime/blob/main/docs/design/features/host-startup-hook.md)
- Reliable compiled-XAML source information requires `ENABLE_XAML_DIAGNOSTICS_SOURCE_INFO=1` before application startup and a build containing `XamlDebuggingInformation=True`. Missing information must remain explicitly unavailable. [Microsoft source-information requirements](https://learn.microsoft.com/en-us/troubleshoot/developer/visualstudio/ide/xaml-hot-reload-troubleshooting)
- WPF's diagnostic visual-tree notifications can be enabled while debugging or through `ENABLE_XAML_DIAGNOSTICS_VISUAL_TREE_NOTIFICATIONS`. Their callback must remain read-only; queue inspection or edits for a later dispatcher operation. These APIs are intended for diagnostic tooling, not production application behavior. [WPF implementation](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationCore/System/Windows/Diagnostics/VisualDiagnostics.cs)
- `PresentationSource.CurrentSources` provides a thread-safe snapshot backed by weak references. Enumerate the sources, then inspect each root through its owning dispatcher; this includes additional windows and popup presentation sources. [PresentationSource.CurrentSources](https://learn.microsoft.com/en-us/dotnet/api/system.windows.presentationsource.currentsources)
- `DiagnosticsClient.ApplyStartupHookAsync` is available, but the protocol describes installing hooks during diagnostic startup suspension, available since .NET 8. It does not establish arbitrary post-startup injection support. [Diagnostics client](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/microsoft-diagnostics-netcore-client#applystartuphook-methods), [IPC protocol](https://github.com/dotnet/diagnostics/blob/main/documentation/design-docs/ipc-protocol.md#applystartuphook)

## Architecture and follow-on work

The separate `net8.0` bootstrap/protocol and `net8.0-windows` WPF agent/shared property editor support untrimmed .NET 8–10 WPF applications. The existing Contracts, Runtime, and PreviewHost projects remain on .NET 10. PreviewHost references the same .NET 8 property-editing library rather than loading its .NET 10 process/lifecycle machinery into target applications. This machine has WindowsDesktop runtimes for .NET 8, 9, and 10, permitting a local compatibility matrix.

Keep the bootstrap free of third-party dependencies. Its initialization should validate session configuration, schedule agent connection, and return promptly. Catch and report its own failures without disrupting the application. Load the agent with controlled dependency resolution; prefer runtime-provided `System.Text.Json` and framed named pipes to introducing RPC package versions into the application's default load context. Never construct a second `Application` or pump a replacement dispatcher.

The agent's tree, dependency-property and binding inspection use existing application objects; the shared editing library owns only temporary property state. PreviewEngine itself overrides design-mode metadata, owns hidden presentation sources, and destroys preview roots; those operations never run in the inspected application. The live agent dispatches each request to the corresponding UI thread. Tree traversal, serialization size, retained object references, operation receipts and request waits are bounded. A timeout reports unavailable or unknown inspection state; it must not terminate the application or handle its exceptions on its behalf.

## Launch and session integration

1. Resolve and build the selected launch target using the existing BuildService pipeline. Require or request XAML debugging information for the instrumented build without silently changing the project file.
2. Create an IDE-owned, current-user named-pipe listener and per-launch nonce. Preserve effective inherited/profile environment values; append the bootstrap path to existing startup hooks, avoiding duplicates. Add session configuration only to the launched application's environment.
3. For debugging, augment `ResolvedLaunch.Environment` before passing it to `DebugLaunchConfiguration`; DebugSession already sends this through DAP `launch.env`. For Run, launch the resolved program after building. Do not install the hook into the `dotnet run` CLI/build process or into the debug adapter.
4. Negotiate protocol version, session nonce, process identity, runtime version, and capabilities before accepting requests. Use bounded, length-prefixed messages with request IDs and cancellation. Disconnect must remove listeners and release agent-held references without shutting down application windows. Avoid propagating WpfStudio's session hook/configuration to child processes while preserving unrelated hooks.
5. Separate process lifetime, tree revision, and source revision. Runtime nodes need weak identities and owning-dispatcher metadata; removed nodes reject operations. Refresh invalidated trees incrementally, with a full snapshot fallback. Pause inspection while the debugger has stopped managed threads; show that state instead of timing out and restarting the session.

## Source and editing limits

**Show XAML** verifies a source hint in stages. The agent reports the actual loaded assembly name/full identity, manifest-module MVID and location, plus the application's resource-assembly identity; it does not infer resource ownership from the selected object's CLR type. It enumerates loaded modules without loading references or reading their files. The catalog preserves duplicate load-context identities and is bounded to 512 modules, 250 ms and 262,144 identity/path characters. Incomplete catalogs are unavailable for source resolution.

The IDE reads the corresponding local PE as data, checks its identity and MVID against the loaded module, then checks an adjacent same-basename portable PDB or embedded portable PDB against that PE's debug identity. It does not follow arbitrary paths from PDB metadata or load project assemblies into the IDE. Compiled `InitializeComponent` resource URI references and PDB sequence points supply the resource-to-document mapping; filename similarity is insufficient. The source document must have a supported SHA-1 or SHA-256 checksum. Symbol reading is bounded to 64 MiB per PE, 32 MiB per PDB and 512 supported source documents, with additional metadata/IL traversal limits.

Before the inspected rebuild, **Verify source on build** (default enabled) opens known workspace `Page` and `ApplicationDefinition` inputs with read sharing only and captures their exact byte hashes. Keeping these handles through the rebuild prevents normal writes between WPF parsing XAML and generating its checksum. Leases cover at most 1,024 files, 8 MiB per file and 64 MiB total; unavailable inputs remain ineligible for navigation or live source edits. A custom target that rewrites those files can fail while they are leased. Turn the option off for that workflow: the next inspected launch captures no source lease and cannot provide verified navigation or live source edits, while tree/binding/property inspection remains available.

Navigation requires the PDB document checksum to match a leased build input. It then checks that the current disk bytes still match and that the open editor text exactly matches the decoded source. The line/column must identify an exact authored object start, with matching element type/name information; an out-of-range offset or a nearby tag is insufficient. Selection, session, debugger pause and workspace changes invalidate pending navigation. Unsaved or external edits are preserved and reported as stale instead of being overwritten or used for unchecked offsets.

These checks verify the hinted source location, not an authenticated origin for every runtime object. Public WPF source hints do not distinguish compiled BAML from loose/custom XAML loaded with a matching base URI. Code-created and generated objects can have no hint. Classless resource dictionaries commonly have no generated `InitializeComponent`/PDB document mapping; their declarations remain unavailable. Duplicate possible module owners, version/public-key-qualified component URIs, unsupported/remote URI forms, missing or truncated symbols, and documents outside the captured workspace inputs remain unavailable. A verified object declaration alone does not identify a binding attribute, style setter, resource declaration or unique template instance.

Runtime edits use an opaque ID for the actual observed dependency property, with owner assembly/CLR type and property name retained for display. They do not resolve an arbitrary client-supplied type or ambiguous display name. Source edits separately account for inherited wrappers and `AddOwner`: different XAML owners may expose the same dependency property. [DependencyProperty.AddOwner](https://learn.microsoft.com/en-us/dotnet/api/system.windows.dependencyproperty.addowner)

For a source proposal, the agent returns verified CLR wrapper or attached-accessor metadata, owner/target module identities and eligible public authored types, including each candidate's content-property and XML namespace metadata. The IDE matches the exact element QName to one candidate and checks its module against the complete current catalog. A subclass-only property on a runtime `MainWindow` cannot be written blindly onto an authored `<Window x:Class="…">`. Ambiguous types/modules, unproven wrappers, read-only properties and unsupported custom converters/providers are unavailable. Source tokens observe the actual property state independently of temporary-edit eligibility: a dynamic resource or OneWayToSource binding may be replaced in source without installing a temporary override.

Explicit value validation parses a bounded scalar and calls the actual dependency property's validation rule; that application callback can run code. It does not call the property's CLR setter, application converter, coercion callback, `SetValue`, `UpdateTarget` or `UpdateSource`. Identity verification and removal do not validate a proposed value. Application-side changes during validation invalidate its observation. Null is distinct from empty text and removal; it writes `{prefix:Null}` only when a matching XAML language alias is already in scope.

`XamlPropertyEditService` parses the original source to prepare precise local attribute, property-element or implicit-content changes. It preserves unrelated declarations, comments and aliases, rejects competing/ambiguous declarations, and reports replacement of bindings, resource expressions and object subtrees in the diff. A style-derived value becomes a local override; removing an authored local value allows style, inheritance or defaults to apply after reload. The workflow does not modify their shared declarations. Editing an element inside a template changes the shared template for all its instances, which the review states explicitly.

Source read leases are released before the review, allowing normal editing and saving. After approval, the IDE refreshes loaded-module evidence, repeats source/file/buffer and property-identity checks, and reacquires the read lease through apply. Selection, draft, source, session, debugger pause and editor changes invalidate a pending proposal, even when changed away and back. A synchronous transaction guard runs after asynchronous disk checks and before buffer mutation. The live application retains its built view and any temporary overrides; the accepted source edit remains a normal unsaved, undoable editor change.

## Acceptance matrix

- Layout observations and rendered overlays: desired/render/actual sizes, parent layout slot, margins, alignment, cached clips, transforms and DPI; rotated elements, RTL, popups and multiple UI dispatchers. Withhold unsupported or pending geometry. Inspect actual adorner drawings, verify normal highlight remains compatible, and clear overlays on removal, pause/resume, selection/session changes, detach and abrupt EOF.

- .NET 8/9/10; DLL and apphost launch; Run and Debug; existing launch-profile variables and other startup hooks preserved.
- Binding failure during startup; application resources; custom controls; multiple windows, popups, and UI dispatchers; virtualized items removed and recreated.
- Missing/incompatible agent, failed handshake, IDE disconnect, stopped debugger, unresponsive dispatcher, application shutdown: application behavior remains intact and owned resources are released.
- Source information enabled/absent; actual loaded MVID and PE/PDB identity; compiled resource aliases and linked files; classless dictionaries without mappings; duplicate module owners, unsupported URI forms and bounded/truncated symbols; stale buffers, changed build bytes and cancelled navigation. Check exact authored element positions and custom-target compatibility with source verification disabled.
- Current binding validation/source/cached-path facts remain separate from historical missing/null/conversion notifications. Check resolved prefixes, first unresolved steps and their null/missing qualification; unsupported private shapes and pending states; exact root/child issue selection, replacement, late replies, pause/disconnect and draft preservation. Check recovery, changed root/nested sources, bounded history and error-content objects without re-evaluating arbitrary model getters.
- Reviewed local source edits: exact authored type versus runtime subclass, inherited/AddOwner/attached identities, namespace aliases, explicit null/empty/removal, binding/resource/object replacements, template scope, diff cancellation/apply/undo, and stale selection/session/property/editor/build evidence before and after review. Shared style/resource-origin edits and broader binding-declaration attribution remain separate work.
- Runtime mutation/reset preserves original local/style/inherited/default precedence; local/style TwoWay and composite binding overrides do not write trial values back to their sources. OneWayToSource rejection leaves its source/binding unchanged. Cover app-replacement conflicts, stale observations, explicit null/empty values, queued cancellation, unknown started callbacks, no-replay receipts, weak target collection, and detach/EOF restoration. Source edits remain reviewable, reversible, and independently validated.
- Unsupported runtime, disabled diagnostics, trimming, and pre-existing uninstrumented processes report their capability limitation without claiming a connected inspector.
